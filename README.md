# AGSL FX

Я собрал библиотеку шейдерных эффектов для Jetpack Compose на **AGSL** (Android Graphics
Shading Language) и демо-приложение-витрину к ней. 8 шейдеров, ноль растровых ресурсов:
всё, что вы видите ниже, целиком посчитано на GPU.

Началось всё с раздражения. Мне надоело, что каждый «стеклянный» блок в интерфейсе на самом
деле подделка — полупрозрачный прямоугольник, который ничего не преломляет, а красивое
свечение под кнопкой оказывается PNG на девять экранных плотностей. AGSL появился ещё в
Android 13, но нормально пользоваться им мешает боилерплейт: руками собери `RuntimeShader`,
руками прокидывай время, руками следи за премультиплицированной альфой. Я это спрятал —
и эффект стал обычным модификатором.

![Каталог эффектов](docs/preview/_sheet.png)

Набор я отбирал не по принципу «чем больше, тем лучше». Изначально эффектов было шестнадцать,
и половину я в итоге выкинул: плёночное зерно, глитч, кинескоп, полиграфический растр,
пиксельную мозаику, звёздное поле. Все они по-своему симпатичные, но вместе с остальными
не складывались ни во что цельное — получался склад приёмов, а не язык. Осталось то, что
держится на геометрии, чистоте и плавности, с жёлто-красным акцентом.

> Проект личный и учебный, к компании Яндекс отношения не имеет — фирменная палитра взята
> просто как жёсткая рамка, внутри которой интереснее работать.

## Быстрый старт

```kotlin
// settings.gradle.kts — модуль уже подключён в этом проекте
include(":agslfx")

// build.gradle.kts вашего модуля
dependencies {
    implementation(project(":agslfx"))
}
```

Эффект — это обычный `Modifier`, никаких обёрток и провайдеров:

```kotlin
// бегущий блик поверх любого контента
Box(Modifier.shimmer())

// живой фон
Box(Modifier.fillMaxSize().meshGradient())

// прогресс с волной на поверхности
Box(Modifier.liquidFill(progress = 0.6f))
```

Свой шейдер подключается тем же ядром — ради этого всё и затевалось:

```kotlin
val MyProgram = AgslProgram(
    name = "My effect",
    body = """
        uniform shader content;
        uniform float2 uResolution;
        uniform float uTime;
        uniform float uAmount;

        half4 main(float2 fragCoord) {
            half4 src = content.eval(fragCoord);
            float wave = sin(fragCoord.y * 0.05 + uTime * 3.0) * uAmount;
            return content.eval(fragCoord + float2(wave * 20.0, 0.0));
        }
    """
)

Box(Modifier.agslEffect(MyProgram) { set("uAmount", 0.5f) })
```

`uResolution` и `uTime` библиотека проставляет сама. В теле доступна мини-стдлиб из
`Agsl.PRELUDE` — то, что я устал переписывать из шейдера в шейдер: `agslHash12`,
`agslNoise`, `agslFbm`, `agslRotate`, `agslLuma`, `agslSdRoundRect`,
`agslPremul` / `agslUnpremul`.

### Палитра

Цветовые дефолты я собрал на жёлтом `#FFCC00`, красном `#FC3F1D`, чёрном и белом.
Это именно дефолты — каждый цвет перекрывается параметром, библиотека вам ничего
не навязывает:

```kotlin
Box(Modifier.duotone())                                   // чёрный → жёлтый
Box(Modifier.duotone(shadow = Navy, highlight = Cyan))    // ваши цвета
```

С `meshGradient` пришлось повозиться отдельно. Первая же четвёрка — жёлтый, красный,
белый и почти чёрный — дала на превью грязно-бежевую кашу: белая точка, смешиваясь
с жёлтым и красным, замыливается. Замена белого на чёрный беж убрала, но посадила
жёлтый в оливковый: рядом с чёрным он всегда мутнеет. В итоге я отказался в этом
эффекте от чёрного и белого вовсе и построил тёплую гамму — `#FFCC00`, `#FC3F1D`
и два моста между ними, `#FF8A00` и `#B32000`. Все переходы остаются внутри одного
тонового семейства, и грязи больше нет.

## Как это устроено

Дальше — три вещи, на которые ушло больше всего времени. Если будете писать своё,
эти грабли, надеюсь, вам не достанутся.

### Кадровое время без рекомпозиции

Наивный способ анимировать шейдер — держать время в `State` и читать его в композабле.
Так я и сделал сначала, и получил рекомпозицию всего поддерева на каждом кадре.

`rememberShaderTime()` возвращает `State<Float>`, который читается **внутри**
`graphicsLayer { }` и `onDraw { }`. Compose отслеживает такие чтения отдельно:
меняется только слой, фаза композиции не запускается вовсе.

```kotlin
return this.graphicsLayer {
    val now = time.value          // чтение в draw-фазе, не в composition
    shader.setFloatUniform("uTime", now)
    renderEffect = RenderEffect
        .createRuntimeShaderEffect(shader, "content")
        .asComposeRenderEffect()
}
```

Время берётся из `withInfiniteAnimationFrameMillis`, поэтому автоматически
замирает там, где Compose останавливает бесконечные анимации — в тестах и `@Preview`.
Приятный побочный эффект: превью в IDE не жгут батарейку.

### Стекло, которое преломляет фон

Вот это меня и раздражало с самого начала. `RenderEffect` в Compose видит только
содержимое **своего** слоя. Размыть то, что нарисовано под композаблом, штатными
средствами нельзя — известное ограничение, из-за которого «стеклянные» панели
почти везде подделывают полупрозрачностью.

`BackdropState` решает задачу честно: фон один раз записывается в `GraphicsLayer`,
а стеклянная панель рисует этот слой **у себя внутри** со сдвигом на свою позицию
в корне и уже к нему применяет AGSL.

```kotlin
val backdrop = rememberBackdrop()

Box(
    Modifier
        .fillMaxSize()
        .meshGradient()
        .backdropSource(backdrop)          // фон пишется в слой
) {
    Box(
        Modifier
            .size(240.dp, 140.dp)
            .clip(RoundedCornerShape(28.dp))
            .liquidGlassBackdrop(backdrop) // панель преломляет именно фон
    )
}
```

В демо эту панель можно таскать пальцем — преломление пересчитывается на лету.
Рекомендую потрогать: на статичной картинке эффект читается заметно хуже, чем вживую.

### Премультиплицированная альфа

На этом я потерял вечер и хочу, чтобы вы не теряли. `content.eval()` возвращает цвет
с **предумноженной** альфой, и результат `main()` Skia тоже ожидает предумноженным.
Поэтому эффекты, которые подмешивают свой цвет, домножают его на `src.a`, а те, что
работают с яркостью (дуотон), сначала зовут `agslUnpremul` и premultiply-ят обратно
на выходе.

Симптом, если этого не сделать: на непрозрачном контенте всё прекрасно, а стоит
подложить что-то полупрозрачное — цвета «съезжают», и совершенно непонятно почему.

### Ограничения AGSL, о которых стоит знать

AGSL — это SkSL в профиле, близком к GLSL ES 2.0:

* циклы обязаны иметь границы, известные при компиляции
  (поэтому число октав `agslFbm` и отсчётов размытия — константы);
* нет рекурсии, нет динамической индексации массивов;
* `half` и `float` живут вместе, но приведения лучше писать явно;
* шейдер компилируется в рантайме — опечатка превращается в исключение при первом
  кадре, а не в ошибку сборки.

Последний пункт — главная боль. Её я решил отдельно.

## Проверка шейдеров без устройства

Мысль простая: AGSL — диалект SkSL, а Skia доступна из Python. Значит те же самые
исходники можно **скомпилировать и отрисовать на CI**, без эмулятора и телефона.

```bash
pip install skia-python

python3 tools/validate_agsl.py     # компилирует все шейдеры, ненулевой код при ошибке
python3 tools/render_previews.py   # рендерит docs/preview/*.png и контактный лист
```

Валидатор ловит не только синтаксис, но и мёртвые униформы — объявленные, но ни разу
не использованные. Некоторые сборки Skia выбрасывают такие при компиляции, и тогда
`setFloatUniform` для них падает уже на устройстве, в рантайме. Крайне неприятный баг,
если искать его руками.

Все превью в этом README отрисованы вторым скриптом из тех же констант, которые
компилируются на устройстве. Картинки не могут разойтись с кодом — это единственный
известный мне способ добиться, чтобы README не начал врать через полгода.

Валидация подключена и как Gradle-задача:

```bash
./gradlew :agslfx:validateAgsl
```
